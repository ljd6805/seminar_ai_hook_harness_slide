OpenCode에서 만드는 Harness

요청을 더 잘 쓰는 데서 그치지 않고, 실행에 적용되는 여섯 가지 규칙을 직접 완성합니다.

실습 키트 v0.12026.10.23

실습 준비

이 실습은 OpenCode 안에서 모델이 실제 도구를 호출하는 과정에 통제를 추가합니다. 가짜 주문 3건의 합계 13000원을 계산해 요약과 보고서를 만들고, 검증한 파일에 대해 사람 승인을 받습니다.

Node.js 22 이상, npm, Git, OpenCode에서 사용할 수 있는 모델 연결이 필요합니다. 기준 버전은 1.19.4입니다. 수업 전 강사가 해당 모델의 도구 호출과 승인 화면을 리허설해야 합니다.

git clone https://github.com/ljd6805/seminar_ai_hook_harness_slide.git
cd seminar_ai_hook_harness_slide
git switch docs/harness-quest-plan-20261023
node --version
npm install -g opencode-ai@1.19.4
opencode --version
node quest/cli.mjs init workshops/quest --level 0
npm install --prefix workshops/quest/.opencode

현재 키트는 Draft PR의 위 브랜치에 있습니다. main에 병합된 뒤에는 브랜치 전환을 생략할 수 있습니다. npm install -g 권한이 없다면 강사가 준비한 1.19.4 실행 파일을 사용하세요.

cd workshops/quest
opencode

사용할 모델을 선택하고 활성 Agent가 quest인지 확인하세요. 모델 선택과 연결은 참가자의 조직에서 허용한 설정을 사용합니다. 자동 승인 옵션을 사용하지 마세요. 전역 플러그인과 권한이 병합될 수 있으므로 수업용 프로필에서 먼저 확인합니다.

두 작업 위치와 반복 절차

위치할 일
저장소 루트 · 터미널 A생성·체크포인트·채점 명령을 실행합니다. 수정 대상은 workshops/quest/learner/rules.mjs입니다.
workshops/quest · 터미널 BOpenCode의 quest Agent에서 미션을 수행합니다. 이 Agent는 정책 파일을 수정할 수 없습니다.

규칙 작성도 OpenCode로 진행할 수 있습니다. 실습 Agent를 종료하고 저장소 루트의 별도 작성 세션에서 아래 요청으로 수정한 뒤, 결과를 읽고 이유를 설명하세요. 익숙한 편집기를 사용해도 됩니다.

workshops/quest/learner/rules.mjs에서 현재 레벨의 함수만 수정해 줘.
내가 설명한 통과 조건을 먼저 정리하고, 최소한으로 바꿔 줘.
quest/lib, 채점기, 이벤트 로그, opencode.json은 수정하지 마.
변경한 조건이 정상 요청과 금지 요청을 어떻게 구분하는지 설명해 줘.
  1. 터미널 B의 OpenCode를 완전히 종료합니다.
  2. 터미널 A에서 해당 레벨의 checkpoint 명령을 한 번 실행합니다.
  3. 규칙을 수정하고 아래 로컬 검사에 통과합니다.
  4. 터미널 B에서 opencode를 다시 실행하고 새 세션으로 미션을 수행합니다.
  5. 실행 증거를 채점하고 로그·산출물을 강사와 대조합니다.
node quest/cli.mjs check workshops/quest
node quest/cli.mjs check workshops/quest --evidence

localPassed는 현재 단계까지의 규칙 검사이고, livePassed는 현재 단계의 실행 증거 검사입니다. --evidence가 없으면 후자는 null입니다. 성공은 종료 코드 0, 미통과는 2, 실행 오류는 1입니다.

checkpoint는 현재 규칙을 백업하고 시작 코드를 다시 씁니다. 같은 레벨의 단순 재시도에는 다시 실행하지 마세요. 규칙을 바꾼 뒤에는 OpenCode를 재시작합니다. 체크포인트는 산출물을 지우지 않습니다.

Lv.0 · 그럴듯한 완료를 의심하기

처음 생성한 Lv.0에서 다음 요청을 입력하세요. 일부러 잘못된 결과를 만들고, 현재 검증기가 무엇을 놓치는지 확인합니다.

quest_write로 lab/output/summary.json에
{"currency":"KRW","itemCount":3,"total":15000}를 써 줘.
quest_write로 lab/output/report.md에 "합계 15000원"을 써 줘.
quest_validate를 한 번 호출해 줘. 아직 제출하지 마.
반환된 ok와 checks의 각 항목이 서로 일치하는지 설명해 줘.

현재 시작 코드는 스키마만 검사하므로 ok: true이면서 sumOK: false, reportOK: false가 나올 수 있습니다. 이것이 고칠 문제입니다. 최종 합계는 원본의 10000 + 5000 − 2000 = 13000입니다.

Lv.0에서는 상세 이벤트 기록도 꺼져 있습니다. .quest/events.jsonl의 강제 로드 표식만으로 업무가 올바르게 완료됐다고 판단하지 마세요.

node quest/cli.mjs checkpoint workshops/quest --level 1

규칙을 수정하고 로컬 검사에 통과하면 실습 폴더에서 OpenCode를 다시 시작하세요. 아래 요청은 새 세션에 입력합니다.

quest_read로 lab/input/orders.json을 읽어 줘.
quest_write로 lab/output/observation.txt에 "Hook 관찰 완료"를 써 줘.
이번에 사용한 도구 이름을 알려 줘.
확인할 결과

.quest/events.jsonl에 before와 after가 생기고 같은 sessionId·callId·도구 이름으로 연결됩니다. 이 Hook은 실제 OpenCode 실행기가 호출합니다.

힌트 열기

shouldRecord가 참을 반환하면 기록이 켜집니다. 연결 코드는 quest/lib/plugin.mjs와 runtime.mjs에 있습니다. 실행 전 거부는 denied로 남으며 모든 오류에서 after가 불린다고 가정하지 않습니다.

새 세션의 첫 8번 요청은 허용되고 9번째는 LIMIT: tool request budget exhausted로 차단됩니다. 거부된 시도도 예산을 소모하며, 상태 조회는 예산에서 제외됩니다. executed에는 상태 조회 자체가 포함됩니다.

첫 세션에서는 OpenCode의 quest_publish 권한 요청을 거절하세요. 제출 기록이 없어야 합니다. 이어서 새 세션에서 같은 요청을 실행하고 이번에는 한 번만 승인하세요. 검증 해시와 같은 이름의 JSON 영수증 하나가 lab/submissions/에 생깁니다. 두 세션의 기록을 함께 채점합니다.

수료 확인과 초기화

Lv.6에서 아래 명령의 로컬 검사 19개와 실행 증거가 모두 통과하는지 확인합니다. 강사는 실제 OpenCode 세션과 권한 화면을 함께 확인합니다. 로그 파일은 참가자가 편집할 수 있으므로 부정행위를 막는 증명 수단은 아닙니다.

node quest/cli.mjs check workshops/quest --evidence
  • 산출물: lab/output/summary.json, lab/output/report.md
  • 승인 후 영수증: lab/submissions/<hash>.json. 실제 외부 게시나 업로드는 하지 않습니다.
  • 관찰 자료: .quest/events.jsonl, .quest/states/
  • 규칙 백업: .quest/backups/. 체크포인트 변경 때만 만들어집니다.

전체를 다시 실습하려면 기존 폴더를 지우는 대신 init workshops/quest-retry --level 0처럼 새 경로를 쓰세요. 예산만 새로 시작하려면 새 세션을 사용합니다. 원본이 바뀌었거나 같은 해시를 이미 제출했다면 새 실습 폴더가 가장 명확합니다.

막혔을 때는 트러블슈팅을 확인하세요. 완성 예제는 rules.mjs에 있으며, 강사는 --solution을 붙여 완성 상태를 만들 수 있습니다. 단위 테스트만으로 실습 수료를 대체하지 않습니다.
