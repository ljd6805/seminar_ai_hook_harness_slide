개발 구조와 실행 계약

작은 정책 함수와 OpenCode의 실행 연결을 분리해, 참가자가 수정한 규칙의 효과를 추적할 수 있게 했습니다.

모든 JS/MJS 소스 파일을 100줄 이하로 유지합니다. 함수 길이도 이 범위 안에 들어갑니다. 생성된 실습 프로젝트에는 실행에 필요한 lib 파일과 플러그인이 복사되며 원본 저장소를 실행 시 참조하지 않습니다.

실행 순서와 상태

  1. OpenCode가 quest 도구를 선택하면 before Hook에서 시도 횟수를 먼저 예약합니다.
  2. 호출 예산 → 도구 허용 목록 → 정규화된 경로 → 검증 재시도 제한 순서로 검사합니다.
  3. 통과하면 실제 파일 작업을 수행합니다. 쓰기는 이전 검증 상태를 무효화합니다.
  4. 검증은 실제 파일을 읽어 체크 결과와 산출물 해시를 저장합니다.
  5. 제출은 조건 확인 → ToolContext.ask → 승인 후 재검사 → 배타적 영수증 생성 순서입니다.

동일 프로세스의 상태 예약은 동기적으로 이뤄집니다. 여러 OpenCode 프로세스가 같은 실습 폴더를 동시에 사용하는 분산 잠금은 제공하지 않습니다. 한 폴더에는 한 실행기를 사용하세요.

해시는 원본·보호 파일·요약·보고서의 정확한 문자열을 함께 묶습니다. 출력의 공백만 바뀌어도 해시는 달라집니다. 승인 뒤 wx 모드로 영수증을 생성해 같은 해시의 중복 파일 생성을 거부합니다.

학습 경계와 알려진 한계

  • 학습 정책이 미완성이어도 lab 밖 경로, 심볼릭 링크, 128KiB 초과 읽기·쓰기를 공통 모듈이 거부합니다. OS 격리나 적대적인 동시 파일 교체까지 보장하는 샌드박스는 아닙니다.
  • 기본 Agent 권한은 모두 거부하고 quest 도구만 허용합니다. quest_publish만 ask이며 제출 도구가 명시적으로 권한을 요청합니다.
  • rules.mjs·채점기·로그는 신뢰하는 수업 자료입니다. 참가자의 직접 수정에 대한 변조 방지나 인증 기능은 없습니다.
  • 보고서는 예상 금액 문자열의 포함 여부만 검사합니다. 의미·문체·근거의 완전성은 검사하지 않습니다.
  • 제출은 로컬 영수증 기록입니다. 원격 게시, 전송, 외부 결제는 없습니다.
  • 상태 조회는 호출 예산에서 제외됩니다. 모델 토큰·비용·시간을 이 예산이 제한한다고 설명하지 않습니다.

개발 검증 명령

npm test
npm run check:source
npm run check:docs
npm install --prefix /tmp/quest-toolchain opencode-ai@1.19.4 @opencode-ai/plugin@1.19.4
node quest/scripts/opencode-smoke.mjs /tmp/quest-toolchain/node_modules/.bin/opencode /tmp/quest-toolchain/node_modules

위 연동 명령은 POSIX 환경 기준입니다. 테스트는 임시 폴더와 별도 XDG 디렉터리를 만들고 고정 응답 서버를 localhost에서 실행합니다. 실제 모델 키 없이 실행하며 권한 요청에는 테스트 클라이언트가 응답합니다. 이 절차는 참가자 본 실습을 대체하지 않습니다.
