AI AGENT SEMINAR · SESSION 02 · OPENCODE WORKSHOP

Harness Quest
OpenCode의 실행을 직접 통제한다.

OpenCode에 실제 업무를 요청하고, 프로젝트 설정과 Hook을 바꾸며 실행 결과를 비교합니다. 도구 호출부터 검증과 사람 승인까지 같은 환경에서 경험합니다.

OpenCode 실습 · 사용자 확정120분 기본안 · 제안Lv.0–6 공동 실습 · 제안기획 기록 · 구현 자료는 교재 참조

이 문서는 구현 전 기획 기록입니다. 이후 OpenCode 1.x를 선택해 기준 버전 1.19.4의 실습 키트를 제작했습니다. 현재 실행 절차는 참가자 교재, 검증 상태는 검증 기록을 우선하세요. 아래의 제작 전·미정 표기는 당시 계획입니다.

문서 허브
01 / DIRECTION

OpenCode에서 실행하고, 그 실행을 직접 통제합니다.

요청

OpenCode에 업무를 맡깁니다.

참가자가 프롬프트를 입력하고 실제 Agent의 도구 호출을 관찰합니다.

확장

설정과 플러그인을 수정합니다.

프로젝트의 권한 설정과 Hook 코드를 바꾸어 통제를 추가합니다.

확인

실제 실행 증거로 비교합니다.

도구 호출 기록, 파일 변경, 검증 결과와 승인 화면을 확인합니다.

구분내용상태
실습 환경본 실습은 OpenCode에서 진행합니다. 실제 OpenCode 실행이 모든 참가자의 필수 학습 과정입니다.사용자 확정
이번 작업 범위실습 기획안부터 작성합니다. 코드·교재·채점기는 다음 제작 단계입니다.사용자 선택
제작 방향OpenCode의 실행 루프·도구·권한 기능 위에 Hook, 상태, 검증 로직을 추가합니다.확정된 환경을 반영한 설계 방향
보조 테스트고정 입력과 단위 테스트는 경계 조건을 반복 검사하는 데 사용합니다. 실제 OpenCode 실행을 대체하지 않습니다.v0.1의 기본 실습 제안을 수정
수료 기준: 참가자가 OpenCode에서 정상 동작과 통제 동작을 실행해 보고, 어디에서 어떤 규칙이 적용됐는지 기록으로 설명합니다. 모의 실행만 확인한 경우에는 OpenCode 실습을 완료했다고 판정하지 않습니다.
02 / SCENARIO

실제 파일로 주문 집계 보고서를 작성합니다.

OpenCode를 실습용 프로젝트에서 실행합니다. Agent는 주문 원본을 읽고 결과 파일을 작성한 뒤 검사 도구를 호출합니다. 참가자는 각 단계에서 기록·정책·한도·검증·승인을 추가합니다.

OpenCode에 입력할 요청 예시

“lab/input/orders.json을 읽어 합계를 계산하고 lab/output/summary.json과 lab/output/report.md를 작성하세요. 지정된 검사 도구로 검증하고, 통과하면 제출 도구를 호출하세요.”

10,000원 + 5,000원 − 할인 2,000원 = 13,000원. 입력·경로·프롬프트는 교재 제작 때 확정합니다.

실제로 확인할 것

  • OpenCode가 파일 읽기·쓰기 도구를 호출합니다.
  • Hook이 그 호출을 관찰하거나 차단합니다.
  • 검사 도구가 실제 산출물을 읽어 판정합니다.
  • OpenCode에서 사람의 승인·거절을 확인합니다.
경로 제안용도통제 대상
lab/input/orders.json가짜 주문 원본읽기는 허용하고 쓰기는 제한합니다.
lab/output/실제 생성할 결과 파일업무 수행 Agent의 쓰기 범위입니다.
lab/protected/settings.json변경 금지 시험용 파일실제 업무 자료 대신 준비한 복사본으로 시험합니다.
lab/output-other/경로 접두사가 비슷한 대조 폴더잘못된 경로 판정이 통과시키는지 검사합니다.
lab/submissions/교육용 제출 기록검증·승인을 거친 제출 도구만 기록합니다.
모의 처리하는 부분은 외부 제출입니다. 보고서 작성·도구 호출·Hook·검증·승인 흐름은 실제 OpenCode에서 확인합니다. 배포·메일 발송 같은 외부 효과는 실습 폴더의 제출 기록으로 대체합니다.

모든 자료는 수업용 복사본으로 준비합니다. 실제 삭제·권한 상승·운영 시스템 변경을 재현할 필요는 없습니다. 권한 설정과 Hook은 교육할 통제 장치이며 완전한 OS 격리를 보장하는 샌드박스로 설명하지 않습니다.

03 / LEARNING FORMAT

설정을 바꾸고 OpenCode에서 다시 실행합니다.

STEP 1미션 입력

OpenCode에 준비된 업무 요청을 입력합니다.

STEP 2설정·Hook 수정

권한 설정 또는 작은 플러그인 함수를 완성합니다.

STEP 3반영·재실행

대상 버전에 맞게 설정을 다시 읽히거나 재시작하고 로드 상태를 확인합니다.

STEP 4증거 확인

도구 호출, 파일 변경과 검증 결과를 채점합니다.

역할담당하는 일
참가자통제 규칙을 설계하고 코드와 설정을 수정합니다. OpenCode의 코드 작성 도움을 받을 수 있습니다.
OpenCode업무 요청을 해석하고 실제 도구를 호출합니다. 본 실습의 실행 환경입니다.
프로젝트 플러그인도구 호출 관찰, 추가 정책 검사, 실행별 상태, 검증과 제출 조건을 연결합니다.
채점기실제 기록과 산출물을 검사합니다. 경계 조건에는 모델 없이 실행하는 보조 테스트도 사용합니다.

코드를 만드는 작업과 통제를 시험하는 작업을 구분합니다.

참가자가 OpenCode로 플러그인을 작성할 때는 작성용 설정을 사용합니다. 통제를 시험할 때는 실습용 Agent 설정과 새 실행 식별자를 사용해, 업무 수행 Agent가 자신의 정책·채점기·기록을 수정하지 못하도록 범위를 좁힙니다. 이 분리는 같은 OpenCode 환경 안에서 진행하며, 모든 참가자가 동시에 여러 Agent를 구동할 필요는 없습니다.

프롬프트만으로 성공을 판정하지 않습니다. Agent가 “하지 않겠다”고 답했거나 기본 권한이 먼저 거부했다면, 참가자가 만든 Hook이 차단한 증거가 아닙니다. 어느 계층에서 거부됐는지 따로 기록하고 Hook을 실제로 거친 요청으로 다시 확인합니다.

이전 Skill Quest의 “미션 → 채점 → 레벨업” 구조는 유지합니다. 별도 Agent 실행기나 시뮬레이터를 본 실습의 중심으로 만들지 않습니다.

Lv.0 · 결과를 확인해 봅니다 10분 · OpenCode에서 시작

수업용 폴더에서 OpenCode를 실행하고 주문 집계 업무를 요청합니다. 대화의 완료 메시지와 실제 산출물·검사 결과를 비교합니다.

학습 장면
통제가 덜 설정된 수업용 프로젝트를 사용하되 기존 제품 권한을 무조건 해제하지 않습니다. 이미 잘못된 합계를 가진 결과 파일을 제공하고 “이 결과를 검증하라”고 요청해 실패 상황을 안정적으로 만듭니다.
통과 기준
원본·산출물·도구 실행 결과를 구분하고, 완료 판정에 필요한 증거를 설명합니다. 모델이 반드시 같은 실수를 하도록 기대하지 않습니다.
Lv.1 · 실제 도구 호출을 기록합니다 15분 · Hook + Record

프로젝트 플러그인의 시작 코드를 수정해 읽기·쓰기·검사 요청을 기록합니다. 해당 버전에 맞는 로드 절차를 수행한 뒤 OpenCode에서 같은 작업을 다시 요청합니다.

참가자 수정
실행 전·후 Hook과 기록 함수의 빈칸을 채웁니다. 정확한 이벤트명과 인자 형식은 대상 OpenCode 버전을 확정한 후 제공합니다.
통과 기준
실제 호출 ID·세션 또는 실행 ID로 시작과 결과를 연결합니다. 성공·오류·차단을 구분하고, 플러그인 버전 표식으로 새 코드가 로드됐음을 확인합니다.
오류 기록
실행 전 Hook에서 거부한 요청은 해당 지점에서 기록합니다. 모든 실패에 실행 후 Hook이 호출된다고 가정하지 않고, 누락 경로를 사전 검증합니다.
Lv.2 · 결과 폴더만 수정하게 합니다 15분 · 파일 범위

실습용 Agent에는 lab/output/ 쓰기를 허용하고 입력 원본·보호 파일·정책 파일 쓰기를 제한합니다. 기본 권한 설정과 추가 Hook 검사의 역할을 따로 확인합니다.

참가자 수정
경로 정책의 조건을 작성합니다. OS별 절대경로 정규화와 기존 경로 또는 부모 경로의 실제 위치 확인은 제공 함수로 처리합니다.
통과 기준
정상 결과 파일은 작성됩니다. 보호 파일, output-other/, 상위 경로 우회 쓰기는 실행 전에 거부되고 기준 파일이 보존됩니다. 여러 파일을 바꾸는 요청은 모든 대상 경로를 확인합니다.
증거
기본 권한이 막은 사례와 Hook이 막은 사례를 각각 표시합니다. 보호 파일 테스트는 미리 만든 폐기 가능한 복사본으로만 진행합니다.
Lv.3 · 도구 권한으로 행동을 제한합니다 15분 · Policy

읽기·쓰기·검사에 필요한 권한은 유지하면서 불필요한 도구와 우회 경로를 제한합니다. 정책이 실제 동작에 어떻게 적용되는지 OpenCode에서 확인합니다.

참가자 수정
실습용 Agent의 허용·거부·승인 필요 규칙을 작성합니다. 도구 이름과 설정 키는 대상 버전의 실제 등록 목록을 기준으로 제공합니다.
통과 기준
허용한 읽기·검사는 성공하고, 지정한 금지 요청은 실행되지 않습니다. Shell·다른 쓰기 도구·하위 Agent·MCP 등 시험 대상 환경에 존재하는 우회 경로도 확인합니다.
범위 제한
Shell은 꼭 필요한 고정 검사만 허용하거나 해당 기능을 검사 전용 도구로 제공합니다. 문자 정규식 하나를 완전한 행동 통제로 설명하지 않습니다.
Lv.4 · 도구 예산과 Agent 반복 한도를 구분합니다 15분 · State + Limits

실습 실행별로 Hook에 도달한 요청 수와 실제 도구 실행 수를 기록합니다. 예산을 넘으면 이후 대상 도구 호출을 거부하고, OpenCode의 Agent 반복 한도도 함께 설정합니다.

참가자 수정
실행별 카운터와 예산 검사 조건을 완성합니다. 예시 예산은 8회이며, 실행 전에 예약합니다. 설정의 Agent 반복 한도는 별도 항목으로 다룹니다.
통과 기준
보조 테스트로 8번째·9번째 요청의 경계를 확인하고, 실제 OpenCode에서 한도 초과 요청의 차단 기록을 확보합니다. 새 실행의 상태가 이전 실행과 섞이지 않습니다.
중요한 구분
Hook에서 오류를 던져 도구를 막는 것만으로 모델 호출과 세션 전체가 끝나는 것은 아닙니다. 도구 횟수, Agent 단계 수, 검증 재시도 횟수는 따로 정의하고 기록합니다.
공통 실습 범위
지원 환경에서 병렬 호출을 제한하거나 원자적 카운터를 제공합니다. 전역 변수 하나로 모든 세션의 횟수를 합치지 않습니다.
Lv.5 · 검증 실패를 OpenCode에 돌려줍니다 15분 · Validation + 재시도

검사 도구가 실제 결과 파일을 읽어 JSON 스키마·항목 수·정수 합계·원본 보존 여부를 판정합니다. OpenCode는 실패 내용을 받아 결과를 수정하고 다시 검사를 요청합니다.

참가자 수정
검사 결과 형식과 재시도 가능 여부를 완성합니다. 잘못된 합계가 있는 파일을 초기 상태로 제공하고 실제 Agent에게 수정하도록 요청합니다.
통과 기준
검사 실패가 도구 결과로 전달되고, 실제 수정·재검증 기록이 남습니다. 최초 검사 후 자동 수정·재검증은 최대 2회로 제한하며, 초과하면 성공으로 표시하거나 제출하지 않습니다.
실패 분류
산출물 오류는 수정할 필드와 기대값을 알려줍니다. 일시적 도구 오류는 한도 내 재시도 대상으로 분류합니다. 권한 위반·승인 거절·예산 소진에는 자동 재시도를 허용하지 않습니다.
검증의 범위
보고서 설명의 품질은 사람의 확인 항목으로 남깁니다. Agent가 “검사했다”고 말해도 실제 검사 도구의 결과가 없으면 통과시키지 않습니다.
Lv.6 · OpenCode의 승인 화면에서 결정합니다 15분 · Approval + 통합

제출 도구에 승인 필요 조건을 연결하고 참가자가 OpenCode에서 승인·거절합니다. 제출 자체는 수업용 폴더에 기록을 추가하는 동작입니다.

참가자 수정
제출 전 검증 조건과 산출물 버전 확인을 완성합니다. 승인은 대상 버전의 공식 권한 요청 기능을 활용하며 별도 승인 UI를 새로 만들지 않습니다.
통과 기준
검증 전 제출은 거부됩니다. 승인 대기·거절 상태에서는 제출 기록이 없고, 검증한 동일 산출물에 대해 한 번 승인한 경우에만 기록이 하나 생깁니다.
승인과 파일의 연결
요청에 대상과 산출물 해시를 포함하고 승인 이후 실행 직전에 다시 비교합니다. 승인 화면이 무엇을 보여주는지, 승인 시점과 Hook·도구 실행의 순서는 시제품 단계에서 확인합니다. 요청만 승인됐다는 이유로 바뀐 파일을 제출하지 않습니다.
승인 실습 운영
자동 승인과 이전의 포괄 승인이 시험을 건너뛰지 않도록 상태를 확인합니다. 일회 승인과 거절을 각각 실습하고, 승인 후 변경·중복 제출은 보조 테스트와 실제 연결 검사로 확인합니다.
Lv.7 자율 과제: 자신이 OpenCode에 맡기는 업무를 하나 골라 적용할 Hook·권한·검증 기준을 설계합니다. 수료 필수 범위에는 넣지 않습니다.
05 / TARGET STRUCTURE

OpenCode가 제공하는 실행 구조 위에 통제를 추가합니다.

본 실습의 실행 경로

참가자 요청→OpenCode Agent→권한 · Hook→실제 도구

학습용 개념도입니다. 권한 요청과 Hook의 정확한 호출 순서는 버전·도구별로 확인합니다.

기존 기능 활용

모델 호출, Agent 반복, 도구 등록·실행, 대화 UI와 기본 권한·승인 흐름은 OpenCode를 사용합니다.

실습에서 추가할 부분

프로젝트 Hook, 필요한 추가 정책, 실행별 상태·예산, 결과 검사와 제출 조건을 작성합니다.

실제 파일 검증

검사 도구가 결과를 읽고 판정합니다. 제출 도구는 유효한 검증과 해당 요청에 대한 승인이 있어야 동작합니다.

채점용 보조 테스트

정책 경계값·반복 한도·승인 후 변경을 고정 입력으로 검사합니다. 실제 OpenCode 연결 증거와 별도로 표시합니다.

OpenCode의 프롬프트에 “규칙을 지켜라”라고 쓰는 것과, 실행 경로에서 규칙을 검사하는 것을 비교합니다. 별도 실행 프레임워크를 만드는 작업은 이 세미나의 범위에 넣지 않습니다.

실행 증거의 최소 항목

OpenCode 버전 · 플러그인 버전 · 모델 식별자
sessionId · labRunId · callId · tool · 대상
정책 판정 · 판정 주체 · 실제 실행 여부 · 검사 결과
산출물 해시 · 승인 요청 식별자 · 제출 여부

필드 이름은 설계 예시입니다. 대상 버전에서 확보할 수 있는 식별자와 이벤트를 확인한 뒤 확정합니다. 제공되지 않는 이벤트를 수집한 것처럼 기록하지 않습니다.

06 / ACCEPTANCE

실제 실행 확인과 반복 검사를 모두 통과해야 합니다.

검사실제 OpenCode 증거보조 테스트
플러그인 로드버전 표식과 실제 읽기·쓰기 Hook 기록기록 형식과 호출 ID 연결
정상 경로정상 파일 작성·검사 통과·승인·제출알려진 입력에 대한 기대 합계
범위 제한실제 금지 요청의 거부 주체와 파일 보존접두사·상위 경로·다중 경로·대상 OS 경계 사례
도구 권한기본 권한 또는 Hook이 거부한 도구 호출미등록 도구와 잘못된 인자
실행 한도도구 예산 소진과 Agent 반복 한도 동작상한 직전·직후, 새 실행 초기화, 병렬 예약
검증·재시도검사 실패 → 실제 수정 → 재검증 또는 한도 도달원본 변경·틀린 합계·재시도 상한
승인OpenCode에서 승인 대기·거절·일회 승인승인 후 변경·다른 요청 승인·중복 제출

모두 차단하는 구현은 통과하지 못합니다. 정상 작업 성공과 금지 행동 차단을 함께 검사합니다. 기록의 “차단” 문구뿐 아니라 도구 실행 여부와 파일의 전후 상태도 확인합니다.

모델이 요청을 호출하지 않는 경우

호출 미발생으로 기록합니다. Hook 차단 성공으로 판정하지 않습니다. 사전 검증한 구체적 시험 프롬프트로 요청하거나 강사가 대상 도구 호출을 확인합니다. 그래도 호출 증거가 없으면 해당 연결 항목은 미확인으로 남깁니다.

모델 응답이 달라지는 경우

문장·호출 순서·총 호출 수가 완전히 같을 것을 요구하지 않습니다. 실제로 검증한 불변 조건을 채점합니다. 경계값의 정확한 검사는 고정 입력 테스트로 보완합니다.

채점 기준은 공개하고 시험 입력의 값은 바꿀 수 있습니다. 정책·검사기·실행 기록은 업무 수행 Agent의 쓰기 범위에서 제외하며, 수업 전후 강사가 기준 배포본과 대조합니다. 실제 업무 비밀값은 사용하지 않습니다.

초보자 지원

미션당 한두 개의 작은 함수를 수정합니다. 힌트는 “관련 개념 → 실패 입력 → 의사코드 → 완성 예제” 순서로 제공합니다. 한 단계에 오래 막히면 체크포인트로 다음 미션을 진행할 수 있게 합니다.

빠른 참가자의 확장

새 경계 사례를 추가하거나 시간 제한을 구현합니다. 다만 병렬 실행, 영속 상태 복구, 실제 OS 격리는 별도 과제로 분리합니다. 수업 중 공통 실습의 범위를 늘리지 않습니다.

학습 난이도 가정: 참가자는 조건문·객체·함수를 읽을 수 있고 OpenCode 기본 사용을 경험했습니다. 설정 반영과 모델 응답 대기 시간이 포함되므로, 120분 배분은 대상 환경의 리허설로 재조정합니다. 참가자 수·OS·모델은 아직 확인되지 않았습니다.
08 / PRODUCTION PLAN

첫 시제품부터 실제 OpenCode에서 검증합니다.

단계완료할 작업문서·증거완료 조건
A · 기획OpenCode 필수 환경을 반영한 미션·통과 기준 정리이 문서와 문서 허브확정 사항과 환경 미결 사항을 구분합니다.
B · 호환성 시제품프로젝트 플러그인 로드, 실제 Hook, 권한 요청, 검사·제출 도구 연결설계 HTML, 버전표, 실제 호출·승인 기록OpenCode 안에서 정상 실행·차단·승인 대기를 확인합니다. 승인 순서와 해시 검증의 구현 가능성을 확인합니다.
C · 실습 키트Lv.0–6의 시작 코드·권한 설정·프롬프트·해답·체크포인트 작성교재 HTML, 강사용 해설 HTML, 단위 테스트각 레벨이 실제 OpenCode에서 재현되고 보조 테스트가 통과합니다.
D · 채점·교육 자료실제 기록 채점, 경계값 검사, 진행 슬라이드 작성검증 보고서 HTML, 슬라이드 HTML정상 해답은 통과하고 준비한 오답은 실패합니다.
E · 리허설깨끗한 목표 환경에서 설치·로드·실습·초기화 실행소요 시간, 모델별 변동, 트러블슈팅 HTML선택한 시간 안에 끝나고 설정 반영·복구 절차가 작동합니다.

제안하는 파일 구성

위치역할
opencode.json프로젝트 설정. 실제 파일명·설정 키는 고정 버전의 사양을 적용합니다.
.opencode/plugins/참가자가 완성할 관찰·검사 Hook과 프로젝트 확장 기능
.opencode/agents/작성 보조와 시험용 Agent의 역할·권한 설정
lab/실제 읽기·쓰기 대상인 가짜 입력, 산출물, 보호용 복사본, 제출 기록
quest/lib/경로 검사·상태·검증 함수. OpenCode 플러그인에서 호출합니다.
quest/missions/레벨별 요청 예시와 변경할 파일·관찰할 결과
quest/checks/실제 실행 증거 검사와 경계값 단위 테스트
quest/checkpoints/단계별 시작 코드·해답·복구 사본
docs/index.html기획·설계·교재·검증·트러블슈팅 문서 허브

위 구성은 구현 제안입니다. 현재는 기획 문서만 존재하며, 도구 정의 위치와 플러그인 API는 버전 확정 후 결정합니다. 별도 Agent 실행기와 선택형 OpenCode 어댑터를 두던 v0.1 구조는 사용하지 않습니다.

구현 기준: 함수는 100줄 이하로 작성합니다. 판정 함수와 부작용을 분리하고 정상·거부·한도·승인 무효화 테스트를 추가합니다. 프로젝트 설정만 사용하며 전역 설정을 바꾸지 않습니다. 개발·검증·문제 해결 문서는 HTML로 작성해 허브에 연결합니다.

교재 제작 전에 고정할 환경

  • 실제 수업에서 사용할 OpenCode 버전, 플러그인 패키지, OS와 실행 런타임을 확인합니다. V1과 V2 코드를 혼합하지 않습니다.
  • 참가자가 사용할 수 있는 모델·인증·동시 호출 제한을 확인합니다. 조직에서 허용된 환경을 사용합니다.
  • 기존 전역 플러그인·권한·자동 승인 상태가 실습에 미치는 영향을 확인합니다.
  • 파일·Shell·하위 Agent·MCP 중 실제 활성화된 경로를 조사해 정책의 적용 범위를 명시합니다.
  • 플러그인 재로드 또는 재시작, 실습 상태 초기화, 승인 이력 처리 절차를 대상 버전으로 검증합니다.
  • 미지원 기능이 있으면 해당 기능의 실습 범위를 수정하고 미지원 사실을 기록합니다. 모의 동작으로 바꾸고 실제 통합 완료라고 표시하지 않습니다.
