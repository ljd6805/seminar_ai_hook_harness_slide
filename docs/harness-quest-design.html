OpenCode 1.x 실습 키트 설계

2026.10.23 · 사용자 선택: OpenCode 1.x. 시제품 검증 기준은 공식 배포본 1.19.4로 고정합니다. 낮은 1.x 버전은 별도 확인이 필요합니다.

구현 결정

  • 프로젝트를 새 실습 폴더에 생성하고, 참가자는 그 폴더에서 OpenCode를 실행합니다.
  • 실제 OpenCode 플러그인으로 quest_read, quest_write, quest_validate, quest_submit, quest_status, quest_probe를 등록합니다. 도구는 실제 수업용 파일에 작용합니다.
  • 학습용 Agent에서는 기본 파일·Shell 도구를 제한합니다. 공통 규칙을 명확히 관찰하도록 작은 실습 도구를 사용하며, 이것도 실제 OpenCode 도구 호출입니다.
  • 수정할 파일은 learner/rules.mjs 한 개로 모읍니다. Lv.1 기록, Lv.2 경로, Lv.3 도구, Lv.4 예산, Lv.5 검증, Lv.6 제출 조건을 순서대로 완성합니다.
  • 파일 경계와 심볼릭 링크 거부는 실행 기반에서 항상 적용합니다. 참가자의 잘못된 정책도 실습 폴더 밖에 영향을 주지 않아야 합니다. OS 수준 샌드박스라는 보장은 하지 않습니다.
  • OpenCode의 ToolContext.ask를 사용해 제출 승인을 받습니다. 승인 전후 검증 해시를 비교하고 동일 산출물의 중복 제출을 거부합니다.
  • 고정 입력 테스트는 로직 검사에 사용합니다. 실제 OpenCode 실행기 연동 테스트와 실제 모델을 사용한 참가자 리허설은 별도 결과로 기록합니다.

제작 순서

  1. 경로·상태·검증·제출의 작은 모듈과 단위 테스트
  2. 1.19.4 플러그인 연결, 프로젝트 생성·체크포인트 CLI
  3. 레벨별 규칙 시작 코드·정답·채점 및 참가자 교재
  4. 실제 OpenCode 실행기 로드·Hook·권한 동작 확인
  5. 검증 보고서·트러블슈팅·문서 허브·PR 갱신

검증 경계

구현과 자동 검증을 마쳤습니다. 현재 결과는 검증 기록, 모듈별 계약은 개발 문서를 확인하세요.

이 환경에는 아직 사용 가능한 모델 연결을 확인하지 않았습니다. 실제 모델 실행이 필요한 검사는 미확인 상태로 유지합니다. 고정 응답 서버를 사용하면 “실제 OpenCode 실행기 + 테스트용 응답”이라고 표시하며 LLM 학습 효과 검증으로 취급하지 않습니다.
