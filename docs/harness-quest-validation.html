실행기 연동의 다섯 시나리오

  1. normal-rejected: 읽기 → 잘못된 합계 쓰기 → 실패 검사 → 수정 → 통과 검사 → 실제 권한 요청 → HTTP 클라이언트가 거절. 영수증 없음.
  2. normal-approved: 같은 작업을 새 세션에서 실행 → 실제 권한 요청 → HTTP 클라이언트가 once 응답. 영수증 하나 생성.
  3. probe-only: 실제 OpenCode가 quest_probe를 요청하고 before Hook이 차단.
  4. path-only: 보호 경로 쓰기 요청을 before Hook이 차단.
  5. limit-only: 순차 읽기 요청 중 아홉 번째를 호출 예산으로 차단.

총 29개의 고정 응답 요청과 65개의 플러그인 이벤트가 기록됐습니다. 이 테스트는 모델 서비스에 접속하지 않습니다. OpenCode 자체는 공식 실행 파일이며, 도구 등록·Hook·권한 API·실제 파일 I/O를 거칩니다.

“실제 OpenCode 연동 통과”는 실제 LLM의 판단이나 사람이 승인 화면을 조작했다는 뜻이 아닙니다. 결과 JSON에도 realLLM: false, humanUI: false를 기록했습니다.

경계 조건 검사

  • 정상 출력은 허용하면서 원본 덮어쓰기·접두사 혼동·경로 탈출·절대 경로를 거부합니다.
  • 일반 심볼릭 링크와 대상이 없는 심볼릭 링크를 모두 거부합니다.
  • 거부된 시도도 예산에 포함하며 동시 요청 12개 중 8개만 실행합니다.
  • 잘못된 합계·원본 변경·불필요한 스키마 키·누락된 산출물을 검사합니다.
  • 검증 전 제출, 승인 거절, 중복 제출, 승인 전후 파일 변경, 다른 세션의 검증 재사용을 검사합니다.
  • 각 레벨의 시작 코드는 현재 검사에 실패하고 완성 예제는 통과합니다.
  • unit-test 출처나 이전 runId의 기록으로 현재 실습을 통과할 수 없습니다.

실행 증거 파일 자체에 대한 암호학적 인증은 없습니다. 채점기는 학습 보조 도구이며 강사의 실제 세션 확인이 필요합니다.

수업 전 남은 확인

강사는 사용할 모델과 OS에서 참가자 교재를 끝까지 수행해야 합니다. 특히 Lv.4에서 도구 호출을 아홉 번 실제 시도하는지, Lv.6의 권한 화면에서 해시를 확인하고 거절·일회 승인이 가능한지 확인합니다. HTML의 모바일·데스크톱 화면과 인쇄 출력도 확인합니다.

기준 버전 외의 OpenCode 1.x, OpenCode 2.x, Windows/macOS, 복수 실행기의 같은 폴더 접근은 이번 검증 범위에 포함되지 않습니다.
