120분을 기본으로 운영하고, 모델의 실제 도구 호출과 사람이 내린 승인 결정을 관찰합니다.

실습 키트 v0.12026.10.23

수업 전 리허설

  1. 수업 OS에서 OpenCode 1.19.4와 Node.js 22 이상을 준비하고 참가자용 모델 연결을 확인합니다.
  2. 새 실습 폴더에서 참가자 교재의 Lv.0–6 요청을 직접 실행합니다.
  3. 전역 플러그인·Agent·MCP·권한이 수업 설정을 바꾸지 않는지 확인합니다. 활성 Agent는 quest여야 합니다.
  4. Lv.6의 권한 화면에 quest_publish와 산출물 해시가 표시되는지, 거절과 일회 승인이 가능한지 확인합니다.
  5. 실제 소요 시간, 모델명, OS, 호출 미발생 사례, 승인 화면 표시 내용을 기록합니다.
현재 검증은 Linux의 실제 OpenCode 실행기와 고정 응답 모델까지입니다. 실제 모델·사람의 TUI 조작·수업 시간·Windows/macOS는 아직 리허설하지 않았습니다.

90분 수업은 사전 설치를 전제로 Lv.1 기록과 Lv.3 도구를 완성 예제로 제공합니다. 준비 10분, Lv.1 5분, Lv.2 15분, Lv.3 5분, Lv.4 15분, Lv.5 20분, Lv.6 15분, 정리 5분으로 운영합니다. 시간은 아직 실측하지 않은 운영안입니다.

단계별 설명 포인트

  • Lv.0: ok라는 이름도 구현이 잘못되면 믿을 수 없습니다. 독립된 합계·원본 검사와 비교합니다.
  • Lv.1: 기록은 통제의 출발점입니다. 플러그인 본체에서 before/after가 등록된 위치를 함께 읽습니다.
  • Lv.2: 경로 접두사와 실제 폴더 경계의 차이를 보여줍니다. 보호 파일을 실제로 망가뜨리는 데모는 필요 없습니다.
  • Lv.3: 학생이 작성한 도구 정책과 OpenCode의 기본 권한을 구분합니다. quest_probe는 무해한 시험 도구입니다.
  • Lv.4: 모델 반복 수와 도구 시도 수를 비교합니다. 병렬 요청의 예산 예약은 자동 테스트로 보완합니다.
  • Lv.5: schemaOK만 검사하는 코드의 한계를 실제 파일로 확인합니다. 보고서 의미 검증은 확장 과제로 남깁니다.
  • Lv.6: 승인은 검증을 대체하지 않습니다. 세션 상태와 승인 전후 해시를 확인합니다.

학습용 코드 수정 범위는 rules.mjs입니다. 핵심 Hook 배선을 처음부터 작성하는 고급 과정이 필요하면 plugin.mjs를 확장 과제로 다룹니다. 기본 과정은 작은 정책 함수를 완성하고 실제 Hook 효과를 관찰하는 데 집중합니다.

채점과 진행 지원

로컬 규칙 검사는 누적됩니다. 실행 증거는 현재 runId의 플러그인 로드·호출 연결·현재 미션을 확인하며 Lv.5–6은 현재 파일도 독립 검사합니다. 체크포인트 이전 기록은 통과 근거가 되지 않습니다.

모델이 금지 도구를 호출하지 않으면 “미호출”로 기록합니다. Hook이 차단했다고 판정하지 마세요. 교재 요청을 새 세션에서 한 번 더 구체적으로 입력하고, 그래도 호출되지 않으면 해당 모델의 리허설 항목으로 남깁니다.

node quest/cli.mjs checkpoint workshops/quest --level 4 --solution
node quest/cli.mjs check workshops/quest

위 명령은 막힌 참가자에게 완성 예제를 제공합니다. 이후 OpenCode를 재시작하고 실제 미션을 진행해야 합니다. 채점기나 로그를 수정해서 통과시키지 않습니다.

Lv.7 선택 확장

기본 과정 이후에만 진행합니다. 보고서의 구조화된 금액 항목 검사, 승인 대기 중 파일 변경 테스트, elapsed-time 제한 중 하나를 선택합니다. 시작 코드·채점 기준은 Lv.0–6까지만 제공하므로 Lv.7은 별도 수료 조건으로 사용하지 않습니다.
