실제 OpenCode로 돌리려면 어디에서 무엇을 실행할까요? Windows PowerShell 예시

PowerShell
# 1. 평소 방법대로 OpenCode 로그인(SSO)을 먼저 마칩니다
# 2. 같은 터미널에서 저장소 루트로 이동합니다

# 3. 브라우저에서 위 주소를 엽니다. 배지가 라이브로 바뀝니다
왜 같은 터미널일까요?

실험실은 로그인을 직접 하지 않습니다. opencode serve를 같은 사용자, 같은 환경 변수로 띄우므로 OpenCode에 저장된 로그인 정보를 그대로 씁니다. serve 안에서는 브라우저 로그인 창이 뜰 수 없습니다.

--opencode "경로"opencode가 PATH에 없거나 사내 전용 실행 파일일 때
--opencode-config "파일"다른 폴더의 opencode.json에 정의한 모델을 쓸 때
--demo모델 대신 고정 응답기로 흐름만 볼 때
--port 4300화면 포트를 바꿀 때

실험실은 OpenCode를 workshops/lab에서 띄웁니다. OpenCode는 전역 설정과 실행한 폴더의 opencode.json만 읽기 때문에, 다른 프로젝트에만 정의한 모델은 보이지 않습니다.

고른 값은 기억됩니다

2부 · 화면 읽기

Record · Limit · Policy

before Hook 안의 칩 세 개는 각각 무엇을 검사할까요?

1Record

본 것과 판단을 .quest/events.jsonl에 남깁니다. 막지 않고 기록만 합니다.

해설 예: record({ event: 'before' })

기록이 없으면 무슨 판단이 있었는지 나중에 알 수 없습니다.
2Limit

세션마다 도구 시도를 셉니다. 정한 횟수를 넘으면 LIMIT으로 막습니다. quest_status는 세지 않습니다.

해설 예: state.attempted 1 ≤ 8 → 통과

같은 도구를 끝없이 부르는 일을 멈춥니다.
3Policy

허용한 도구인지, 허용한 경로인지 봅니다. 아니면 POLICY로 막습니다.

해설 예: allowedTools · 허용 경로 → 막음

해서는 안 되는 행동을 실행 전에 거릅니다.

세 칩은 위에서부터 차례로 검사합니다. 하나라도 throw하면 그 자리에서 멈추고 도구는 실행되지 않습니다.

    Approval 칸canSubmit()을 통과하면 OpenCode가 사람에게 묻습니다. 실행이 여기서 멈춥니다.
  3. 3
    [한 번 허용] · [거절]"항상 허용"은 일부러 두지 않았습니다. 승인은 한 번에 한 건씩만 합니다.
  4. 4
    도구 실행은 승인 대기허용하면 로컬 영수증을 한 번만 만들고, 거절하면 오류로 끝납니다.

화면이 실제 실행보다 뒤처져 있을 때 승인 요청이 오면, 요청 칸 아래에 "승인 단계로 가기" 버튼이 뜹니다. 누르면 그 장면으로 바로 건너뜁니다.

3부 · 첫 실행

새 세션 · 중단 · 파일 비우기

같은 실험을 깨끗한 상태에서 다시 하려면 무엇을 누를까요?

새 세션

시도 횟수(예산)와 검증 횟수를 0부터 다시 셉니다. Limit 실험을 반복할 때 먼저 누릅니다.

중단

돌고 있는 Agent를 멈춥니다. Agent가 도는 동안에는 보내기·새 세션·파일 비우기가 잠기고 중단만 누를 수 있습니다.

파일 비우기

지난 실험에서 만든 lab/output 파일을 지웁니다. 이전 결과가 다음 실험에 섞이지 않게 합니다.

보내기를 누르면 코드가 먼저 적용됩니다

Harness 코드를 바꾸면 요청 칸 위에 "코드가 바뀜 · 보낼 때 적용"이 보입니다. 보내기를 누르면 그 코드를 먼저 적용하고 요청을 보냅니다. 라이브 모드에서는 harness.js를 실습 폴더에 쓰고 OpenCode를 다시 띄우므로 새 세션이 시작됩니다. 문법 오류가 있으면 적용하지도 보내지도 않습니다.

검사하기는 고정 입력으로 돌려 보는 것입니다. 실제로 막히는지는 적용한 뒤 요청을 보내 머신에서 확인합니다. 예를 들어 Policy(경로)만 쓰고 적용하면 보호 파일 수정은 막히지만 quest_probe는 그대로 실행됩니다.

머신은 내 코드를 읽어 그립니다

화면의 머신은 적용한 코드가 실제로 무엇을 하는지(Limit이 있는지, 몇 회에서 막는지 등)를 같은 검사로 알아내 그립니다. 그래서 칩이 흐리게 보이면 그 장치가 코드에 아직 없다는 뜻입니다.

실험실을 다 돌고 나면 무엇을 설명할 수 있어야 할까요?

  • 패킷 한 바퀴가 도구 호출 한 번이라는 것과, 막힐 때 패킷이 어디로 가는지 설명할 수 있습니다.
