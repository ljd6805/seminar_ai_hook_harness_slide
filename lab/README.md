# Hook·Harness 실험실

요청을 보내면 OpenCode가 실제로 도구를 호출하고, Harness Quest 플러그인의 Hook이 그 호출을 어떻게 판단하는지 흐름도와 로그로 보여 주는 실험실입니다. 규칙은 화면에서 직접 바꿔 볼 수 있습니다.

## 세 가지 모드

| 모드 | 여는 방법 | 무엇이 실행하나 |
|---|---|---|
| 라이브 | `node lab/server.mjs` 실행 후 `http://127.0.0.1:4300/` | 실제 OpenCode 1.19.4와 사용자가 연결한 모델 |
| 미리보기 | `lab/index.html`을 그냥 열기 (GitHub Pages 포함) | 브라우저 안 모의 실행기. 판단 순서는 플러그인과 같고, Agent는 요청 낱말로 고르는 고정 시나리오입니다 |
| 기록 재생 | 어느 모드에서나 "기록 재생" 탭 | `quest/evidence/opencode-events.jsonl` 또는 직접 고른 `events.jsonl` |

## 라이브 모드 실행

준비물은 저장소 README와 같습니다: Node.js 22 이상, `opencode-ai@1.19.4`, OpenCode에 연결된 모델.

```sh
# 저장소 루트에서
node lab/server.mjs
# 브라우저에서 http://127.0.0.1:4300/ 열기
```

처음 실행하면 `workshops/lab/`에 실습 폴더를 만듭니다. npm으로 따로 설치하는 것은 없습니다. 플러그인이 `@opencode-ai/plugin`에서 쓰는 것은 `tool()` 하나뿐이라서, 같은 동작을 하는 사본(`lab/vendor/`, zod 4.1.8 포함)을 실습 폴더에 연결하고 OpenCode가 시작할 때 이 패키지를 내려받으려는 단계도 건너뛰게 해 둡니다. 그래서 사내 npm 미러에 패키지가 없거나 인터넷이 막혀 있어도 실험실은 돕니다. 서버는 그 폴더에서 `opencode serve`를 띄우고, 두 가지 신호를 하나로 합쳐 화면에 보냅니다.

- OpenCode 이벤트 스트림(`/event`): 도구 호출 시작·완료·오류, 승인 요청, Agent 응답
- 플러그인 기록(`.quest/events.jsonl`): Hook의 `before`·`denied`·`after`·`validation`·`approval_*`·`submitted`

옵션은 다음과 같습니다.

| 옵션 | 뜻 |
|---|---|
| `--port 4300` | 실험실 화면 포트 |
| `--workspace <폴더>` | 실습 폴더 위치 (기본 `workshops/lab`) |
| `--opencode <경로>` | `opencode` 실행 파일 경로 (PATH에 없을 때) |
| `--demo` | 모델 대신 키트의 고정 응답기를 씁니다. 요청에 `probe-only`, `path-only`, `limit-only`를 넣으면 해당 장면이, 그 밖의 요청은 정상 흐름이 재생됩니다 |

## 에뮬레이터 컨트롤

OpenCode와 Hook이 만드는 사건은 모두 **테이프**에 쌓이고, 화면은 테이프의 처음부터 **플레이헤드**까지를 다시 계산해서 그립니다. 그래서 실제 실행이 순식간에 끝나도 한 단계씩 천천히 볼 수 있고, 앞뒤로 되감을 수도 있습니다.

| 조작 | 하는 일 |
|---|---|
| ▶ / ⏸ (Space) | 재생·일시정지 |
| ◀ · ▶| (← →) | 한 단계 뒤·앞 |
| ⏮ (Home) · LIVE (End) | 처음으로 · 실시간 위치로 |
| 타임라인 클릭, 로그 줄 클릭 | 그 단계로 이동 |
| 타임 조그다이얼 (드래그·휠, ↑ ↓) | 재생 중에는 단계 사이 간격(0~5초)을 바꾸고, 멈춘 상태에서는 한 칸(24°)마다 한 단계씩 움직입니다 |

가운데 머신은 Agent 루프를 Harness가 감싸는 모양입니다. 사용자의 요청이 Agent(LLM)에 들어가면 패킷이 시계 방향으로 돕니다: ① 도구 호출 → before Hook → ② 허용되면 실행 → ③ 결과 → after Hook → ④ 관찰 → 다시 Agent. 한 바퀴가 도구 호출 한 번이고, 가운데 숫자가 이번 요청에서 몇 번째 호출인지 알려 줍니다. before Hook이 막으면 패킷은 실행을 건너뛰고 안쪽 점선을 따라 Agent로 되돌아갑니다. `quest_validate`와 `quest_submit`은 실행 안에서 아래 줄의 Validation·Approval·제출을 거칩니다. Agent가 더 부를 도구가 없으면 루프를 빠져나와 사용자에게 응답합니다.

before Hook 한 번은 ① Record → ② Limit → ③ Policy 세 단계로 펼쳐서 보여 줍니다. 오른쪽 레지스터(TOOL·ARGS·ATTEMPT·VALIDATION·LAST CHECK·SUBMIT)는 바뀐 칸이 반짝이고, "현재 단계"에는 그 판정이 왜 그렇게 나왔는지 설명과 원본 사건이 나옵니다.

라이브에서 OpenCode 이벤트는 HTTP 스트림으로, Hook 기록은 파일로 와서 도착 순서가 뒤집힐 수 있습니다. 화면은 같은 도구의 호출과 Hook을 짝지어 "호출 → Hook" 순서로 테이프를 맞추고, 승인 요청은 `approval_requested` 기록이 온 뒤에 보여 줍니다.

## 화면에서 할 수 있는 일

- **요청**: 직접 쓰거나 예시 요청을 골라 보냅니다. 승인 요청이 오면 머신의 Approval 칸에서 [한 번 허용]이나 [거절]을 누릅니다. "항상 허용"은 일부러 두지 않았습니다.
- **Harness 꾸미기**: Record 켜기·끄기, 허용 도구, 읽기·쓰기 경로, 예산, 검증 조건, 제출 조건, 승인 방식(ask·allow·deny)을 바꿉니다. 만들어지는 `learner/rules.mjs`를 보고 직접 고칠 수도 있습니다. 라이브 모드에서 적용하면 실습 폴더의 `rules.mjs`, `.quest/settings.json`(예산), `opencode.json`(승인 방식)을 쓰고 OpenCode를 다시 시작합니다.
- **새 세션**: 예산과 검증 횟수는 세션마다 셉니다. 처음부터 다시 세려면 새 세션을 시작합니다.

## 해 볼 만한 실험

1. "맨몸 Agent"를 적용하고 합계 요청을 보냅니다. 검증이 스키마만 보기 때문에 틀린 합계 15000원이 완료로 처리됩니다.
2. 같은 상태에서 보호 파일 수정을 요청합니다. 쓰기가 그대로 실행됩니다. 그다음 "완성 Harness"로 바꾸고 다시 요청하면 Policy가 막습니다.
3. Record를 끄고 요청을 보냅니다. Agent 쪽 로그는 남지만 Hook 칸은 움직이지 않습니다. 기록이 없으면 무슨 판단이 있었는지 알 수 없다는 점을 확인합니다.
4. 예산을 3으로 줄이고 합계 요청을 보냅니다. 네 번째 도구 시도에서 Limit이 막습니다.

## Windows·사내망에서 실행할 때

- 저장소를 공백이나 한글이 들어간 폴더(예: `D:\종덕 업무\...`)에 두어도 됩니다. `opencode`나 `npm`이 `.cmd` 파일이면 경로를 따옴표로 감싸서 실행하고, `.exe`면 셸 없이 바로 실행합니다.
- 필요한 것은 `opencode` 실행 파일과 OpenCode에 연결된 모델뿐입니다. `opencode-ai`를 사내 미러에서 받을 수 없으면 OpenCode 배포 파일을 따로 받아 `--opencode <경로>`로 지정합니다.
- 모델 없이 흐름만 보려면 `--demo`를 붙입니다. 고정 응답기는 이 컴퓨터 안에서만 돕니다.

## 확인한 범위

- 컨테이너(Linux, Node 22)에서 실제 OpenCode 1.19.4와 `--demo` 고정 응답기로 확인했습니다: 정상 흐름, 화면에서 승인 허용·거절, 금지 도구 거부, 금지 경로 거부, 규칙 변경 후 재시작 반영, 이벤트 순서 맞춤, 멈춘 상태의 조그 되감기.
- 경로에 공백·한글·괄호가 있고 npm 레지스트리에 닿을 수 없는 상태에서, 새 실습 폴더로 요청부터 승인·제출까지 확인했습니다(Linux).
- 실제 모델, Windows·macOS에서는 아직 실행해 보지 않았습니다. Windows용 실행 방식(따옴표 처리, `.cmd`·`.exe` 구분)은 코드로만 맞춰 두었습니다.
- 서버는 `127.0.0.1`에만 열립니다. 신뢰하는 개인 학습용이며 보안 격리를 제공하지 않습니다.
