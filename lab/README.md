# Hook·Harness 실험실

요청을 보내면 OpenCode가 실제로 도구를 호출하고, Harness 플러그인의 Hook이 그 호출을 어떻게 판단하는지 흐름도와 로그로 보여 주는 실험실입니다. Harness 코드(`.opencode/plugins/harness.js`)는 화면에서 직접 만듭니다.

## 세 가지 모드

| 모드 | 여는 방법 | 무엇이 실행하나 |
|---|---|---|
| 라이브 | `node lab/server.mjs` 실행 후 `http://127.0.0.1:4300/` | 실제 OpenCode 1.19.4와 사용자가 연결한 모델 |
| 미리보기 | `lab/index.html`을 그냥 열기 (GitHub Pages 포함) | 브라우저 안 모의 실행기. 적용한 `harness.js`를 그대로 실행하고, Agent는 요청 낱말로 고르는 고정 시나리오입니다 |
| 기록 재생 | 어느 모드에서나 "기록 재생" 탭 | `quest/evidence/opencode-events.jsonl` 또는 직접 고른 `events.jsonl` |

## 라이브 모드 실행

준비물은 저장소 README와 같습니다: Node.js 22 이상, `opencode-ai@1.19.4`, OpenCode에 연결된 모델.

```sh
# 저장소 루트에서
node lab/server.mjs
# 브라우저에서 http://127.0.0.1:4300/ 열기
```

처음 실행하면 `workshops/lab/`에 실습 폴더를 만듭니다. npm으로 따로 설치하는 것은 없습니다. 플러그인이 `@opencode-ai/plugin`에서 쓰는 것은 `tool()` 하나뿐이라서, 같은 동작을 하는 사본(`lab/vendor/`, zod 4.1.8 포함)을 실습 폴더에 연결하고 OpenCode가 시작할 때 이 패키지를 내려받으려는 단계도 건너뛰게 해 둡니다. 그래서 사내 npm 미러에 패키지가 없거나 인터넷이 막혀 있어도 실험실은 돕니다. 서버는 그 폴더에서 `opencode serve`를 띄우고, 두 가지 신호를 하나로 합쳐 화면에 보냅니다.

- OpenCode 이벤트 스트림(`/event`): 도구 호출 시작·완료·오류, 승인 요청, Agent 응답
- 플러그인 기록(`.quest/events.jsonl`): Hook의 `before`·`denied`·`after`·`validation`·`approval_*`·`submitted`

옵션은 다음과 같습니다.

| 옵션 | 뜻 |
|---|---|
| `--port 4300` | 실험실 화면 포트 |
| `--workspace <폴더>` | 실습 폴더 위치 (기본 `workshops/lab`) |
| `--opencode <경로>` | `opencode` 실행 파일 경로 (PATH에 없을 때) |
| `--model <공급자/모델>` | 기본으로 쓸 모델. 환경 변수 `LAB_MODEL`로도 줄 수 있습니다 |
| `--opencode-config <파일>` | 평소 쓰는 `opencode.json`을 함께 읽습니다(`OPENCODE_CONFIG`로 전달) |
| `--demo` | 모델 대신 키트의 고정 응답기를 씁니다. 요청에 `probe-only`, `path-only`, `limit-only`를 넣으면 해당 장면이, 그 밖의 요청은 정상 흐름이 재생됩니다 |

## 에뮬레이터 컨트롤

OpenCode와 Hook이 만드는 사건은 모두 **테이프**에 쌓이고, 화면은 테이프의 처음부터 **플레이헤드**까지를 다시 계산해서 그립니다. 그래서 실제 실행이 순식간에 끝나도 한 단계씩 천천히 볼 수 있고, 앞뒤로 되감을 수도 있습니다.

| 조작 | 하는 일 |
|---|---|
| ▶ / ⏸ (Space) | 재생·일시정지 |
| ◀ · ▶| (← →) | 한 단계 뒤·앞 |
| ⏮ (Home) · LIVE (End) | 처음으로 · 실시간 위치로 |
| 타임라인 클릭, 로그 줄 클릭 | 그 단계로 이동 |
| 타임 조그다이얼 (드래그·휠, ↑ ↓) | 재생 중에는 단계 사이 간격(0~5초)을 바꾸고, 멈춘 상태에서는 한 칸(24°)마다 한 단계씩 움직입니다 |
| 머신 아래 [◀ 이전 단계]·[다음 단계 ▶] | 한 단계씩 앞뒤로 넘깁니다. 가운데에 지금 몇 번째 단계인지와 아직 보지 않은 단계 수가 나옵니다 |
| "한 단계씩 보기" 체크 | 켜 두면 요청을 보내도 자동으로 재생하지 않고, [다음 단계 ▶]를 누를 때만 진행합니다. 설정은 브라우저에 기억됩니다 |
| 오른쪽 위 [? 가이드] (← → Enter Esc) | 화면의 각 영역을 차례로 비추며 설명합니다. 처음 열 때 한 번 자동으로 뜹니다 |

가운데 머신은 Agent 루프를 Harness가 감싸는 모양입니다. 사용자의 요청이 Agent(LLM)에 들어가면 패킷이 시계 방향으로 돕니다: ① 도구 호출 → before Hook → ② 허용되면 실행 → ③ 결과 → after Hook → ④ 관찰 → 다시 Agent. 한 바퀴가 도구 호출 한 번이고, 가운데 숫자가 이번 요청에서 몇 번째 호출인지 알려 줍니다. before Hook이 막으면 패킷은 실행을 건너뛰고 안쪽 점선을 따라 Agent로 되돌아갑니다. `quest_validate`와 `quest_submit`은 실행 안에서 아래 줄의 Validation·Approval·제출을 거칩니다. Agent가 더 부를 도구가 없으면 루프를 빠져나와 사용자에게 응답합니다.

before Hook 한 번은 ① Record → ② Limit → ③ Policy 세 단계로 펼쳐서 보여 줍니다. 오른쪽 레지스터(TOOL·ARGS·ATTEMPT·VALIDATION·LAST CHECK·SUBMIT)는 바뀐 칸이 반짝이고, "현재 단계"에는 그 판정이 왜 그렇게 나왔는지 설명과 원본 사건이 나옵니다.

라이브에서 OpenCode 이벤트는 HTTP 스트림으로, Hook 기록은 파일로 와서 도착 순서가 뒤집힐 수 있습니다. 화면은 같은 도구의 호출과 Hook을 짝지어 "호출 → Hook" 순서로 테이프를 맞추고, 승인 요청은 `approval_requested` 기록이 온 뒤에 보여 줍니다.

### 모델과 로그인(SSO)

모델 선택 박스의 기본값은 "OpenCode 기본 모델 사용"입니다. 이때 실험실은 모델을 지정하지 않고 요청을 보내므로, OpenCode가 평소 설정의 기본 모델을 씁니다. 다른 모델로 보내고 싶을 때만 목록에서 고르면 됩니다.

로그인은 실험실이 하지 않습니다. 실험실은 `opencode serve`를 같은 사용자, 같은 환경 변수로 띄우므로 OpenCode에 저장된 로그인 정보(OAuth SSO 포함)와 전역 설정·플러그인을 그대로 씁니다.

1. 평소처럼 OpenCode에서 SSO 로그인을 먼저 마칩니다. 브라우저 로그인 창은 `serve` 안에서는 뜰 수 없습니다.
2. 같은 터미널에서 실험실을 실행합니다. 사내 실행 스크립트가 `OPENCODE_CONFIG_DIR` 같은 환경 변수를 세팅한다면 그 변수가 켜진 셸이어야 합니다.
3. 사내 OpenCode가 별도 실행 파일이면 `--opencode "그 경로"`로 지정합니다.

### 모델이 목록에 안 보일 때

실험실은 OpenCode를 `workshops/lab` 폴더에서 띄웁니다. OpenCode는 전역 설정(`~/.config/opencode/opencode.json`)과 실행한 폴더의 `opencode.json`만 읽으므로, 다른 프로젝트 폴더의 `opencode.json`에 정의한 공급자·모델은 목록에 나오지 않습니다.

1. 평소 쓰던 폴더에서 `opencode models`로 정확한 이름(예: `회사공급자/gpt-6-luna`)을 확인합니다.
2. 그 모델이 프로젝트 `opencode.json`에 정의되어 있다면 `node lab/server.mjs --opencode-config "그 파일 경로"`로 실행합니다.
3. 화면의 모델 선택 박스 맨 아래 "직접 입력…"을 고르면 목록에 없는 `공급자/모델`을 적을 수 있습니다. 고른 모델은 브라우저에 기억됩니다.

`--demo`로 한 번 실행한 뒤 일반 모드로 다시 띄우면, 실습 폴더에 남아 있던 데모 공급자 설정은 자동으로 지웁니다.

## Harness 만들기

Harness는 `.opencode/plugins/harness.js` 한 파일입니다. `tool.execute.before`에서 기록하고(Record), 횟수를 세고(Limit), 도구와 경로를 검사해(Policy) 막을 때는 `throw`합니다. `tool.execute.after`는 결과를 기록합니다. 검증 조건(`acceptValidation`)과 제출 조건(`canSubmit`)도 같은 파일에 있습니다. 작업 도구(`quest_*`)와 세션 횟수 보관·기록 파일 쓰기는 `lab/kit/kit.mjs`가 맡고, 이 파일은 판단을 하지 않습니다.

- **기본 과정**: Record·Limit·Policy(도구·경로)를 켜고 끄거나 값을 바꾸면, 옆의 실제 코드가 다시 만들어지고 새로 생긴 줄은 초록, 빠진 자리는 빨간 선으로 잠깐 표시됩니다. 폼 상자에 마우스를 올리면 그 상자가 만든 줄만 밝게 보입니다.
- **고급 과정**: 빈 뼈대에서 시작해 직접 씁니다. 미션은 Hook 등록, Record, Policy(경로), Policy(도구), 막은 이유 기록, Limit, Validation, 제출 조건의 8개입니다. **검사하기**는 고정 입력으로 코드를 돌려 미션별 통과 여부와 다음에 고칠 점을 알려 줍니다. 막히면 미션마다 예시 코드를 펼쳐 볼 수 있고, **기본 과정 코드 가져오기**로 완성 예제를 편집기에 넣을 수도 있습니다. 쓰던 코드는 브라우저에 저장됩니다.
- Harness 코드와 요청은 한 화면(**실험** 탭)에 있습니다. 아래 **요청** 칸에서 예시를 고르거나 직접 써서 **보내기**를 누르면, 코드가 바뀐 경우 먼저 그 코드를 적용하고(라이브는 OpenCode가 다시 뜰 때까지 기다림) 요청을 보냅니다. 그래서 화면에 보이는 코드가 언제나 실행되는 Harness입니다. 아직 적용되지 않은 변경이 있으면 요청 칸 위에 "코드가 바뀜 · 보낼 때 적용"이 보입니다.
- 적용할 때 라이브 모드에서는 코드를 실습 폴더의 `harness.js`에 그대로 쓰고 OpenCode를 다시 시작합니다(새 세션). 문법 오류가 있으면 적용하지도 보내지도 않습니다. 미리보기에서는 브라우저 안에서 같은 코드를 실행합니다. 화면의 머신은 적용한 코드가 실제로 무엇을 하는지(Limit이 있는지, 몇 회에서 막는지 등)를 같은 검사로 알아내 그립니다.
- 검사는 고정 입력으로 돌려 보는 것이라 실제 OpenCode 실행을 대신하지 않습니다. 적용한 뒤 예시 요청을 보내 머신에서 실제로 막히는지 확인합니다.

코드 생성기와 검사기는 `lab/kit/harness-source.mjs` 하나이고, 서버와 화면이 같이 씁니다. 화면(`lab/index.html`)을 고치려면 `lab/src/index.template.html`을 고친 뒤 `npm run lab:build`로 다시 만듭니다.

## 화면에서 할 수 있는 일

- **요청**: 실험 탭 아래 칸에 직접 쓰거나 예시를 고릅니다. 예시마다 어떤 장면(정상 흐름, Policy가 경로를 막음, Limit이 횟수를 막음 등)을 보게 되는지 함께 적혀 있습니다. 승인 요청이 오면 머신의 Approval 칸에서 [한 번 허용]이나 [거절]을 누릅니다. "항상 허용"은 일부러 두지 않았습니다.
- **Harness 만들기**: 위 설명대로 기본 과정이나 고급 과정으로 `harness.js`를 만듭니다. 사람에게 승인을 물을지(ask·allow·deny)는 `opencode.json`의 `quest_publish` 권한으로 정하고, 적용할 때 함께 씁니다.
- **실행 관리**: [새 세션]은 예산과 검증 횟수를 처음부터 다시 셉니다. [중단]은 진행 중인 Agent를 멈춥니다. [파일 비우기]는 Agent가 만든 결과 파일을 지워 같은 실험을 깨끗한 상태에서 다시 하게 합니다.
- **화면 배치**: 왼쪽 실험 탭은 위에 Harness 코드, 아래에 요청과 실행 관리가 있습니다. 가운데는 머신과 단계 버튼, 오른쪽은 위에서부터 현재 단계 설명, 상태 레지스터, 로그 순서입니다.

## 해 볼 만한 실험

1. 기본 과정에서 "맨몸 Agent"를 적용하고 합계 요청을 보냅니다. 검증이 스키마만 보기 때문에 틀린 합계 15000원이 완료로 처리됩니다.
2. 같은 상태에서 보호 파일 수정을 요청합니다. 쓰기가 그대로 실행됩니다. 그다음 "완성 Harness"로 바꾸고 다시 요청하면 Policy가 막습니다.
3. Record를 끄고 요청을 보냅니다. Agent 쪽 로그는 남지만 Hook 칸은 움직이지 않습니다. 기록이 없으면 무슨 판단이 있었는지 알 수 없다는 점을 확인합니다.
4. Limit을 3회로 줄이고 합계 요청을 보냅니다. 코드의 `state.attempted > 3`이 네 번째 도구 시도를 막습니다.
5. 고급 과정에서 미션을 하나씩 풀며 적용해 봅니다. 예를 들어 Policy(경로)만 쓴 상태로 적용하면 보호 파일 수정은 막히지만 `quest_probe`는 그대로 실행됩니다.

## Windows·사내망에서 실행할 때

- 저장소를 공백이나 한글이 들어간 폴더(예: `D:\종덕 업무\...`)에 두어도 됩니다. `opencode`나 `npm`이 `.cmd` 파일이면 경로를 따옴표로 감싸서 실행하고, `.exe`면 셸 없이 바로 실행합니다.
- 필요한 것은 `opencode` 실행 파일과 OpenCode에 연결된 모델뿐입니다. `opencode-ai`를 사내 미러에서 받을 수 없으면 OpenCode 배포 파일을 따로 받아 `--opencode <경로>`로 지정합니다.
- 모델 없이 흐름만 보려면 `--demo`를 붙입니다. 고정 응답기는 이 컴퓨터 안에서만 돕니다.

## 확인한 범위

- 컨테이너(Linux, Node 22)에서 실제 OpenCode 1.19.4와 `--demo` 고정 응답기로 확인했습니다: 정상 흐름, 화면에서 승인 허용·거절, 금지 도구 거부, 금지 경로 거부, 규칙 변경 후 재시작 반영, 이벤트 순서 맞춤, 멈춘 상태의 조그 되감기.
- 기본·고급 과정에서 만든 `harness.js`를 적용해 실제 OpenCode가 그 코드로 막는 것(예: 직접 고친 예산 2회)을 확인했습니다.
- 경로에 공백·한글·괄호가 있고 npm 레지스트리에 닿을 수 없는 상태에서, 새 실습 폴더로 요청부터 승인·제출까지 확인했습니다(Linux).
- 실제 모델, Windows·macOS에서는 아직 실행해 보지 않았습니다. Windows용 실행 방식(따옴표 처리, `.cmd`·`.exe` 구분)은 코드로만 맞춰 두었습니다.
- 서버는 `127.0.0.1`에만 열립니다. 신뢰하는 개인 학습용이며 보안 격리를 제공하지 않습니다.
